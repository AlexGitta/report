# Supabase backend

Postgres + PostGIS schema, RLS and RPCs for the Local Problem Reporter (see `docs/PLAN.md` §3, §5, §6, §8).

## Run locally

```sh
npx supabase start        # first run pulls the Docker images (large)
npx supabase status       # API URL, anon key, Studio (http://localhost:54323), Mailpit (http://localhost:54324)
npx supabase db reset     # re-apply migrations + seeds from scratch
npx supabase stop
```

Anonymous sign-ins are enabled in `config.toml` (`[auth] enable_anonymous_sign_ins = true`). The app should
call `supabase.auth.signInAnonymously()` for guests so they have an `auth.uid()` (needed to upload photos,
post updates and see their own reports).

## Layout

| Path | What |
|---|---|
| `migrations/20260926120000_init.sql` | Enums, tables, triggers, RLS, views, RPCs, storage bucket + policies |
| `seed.sql` | The 14 categories (slugs are a shared contract, see below) |
| `seed_authorities.sql` | English councils (E06/E07/E08/E09/E10), generated by `data/build_authorities.mjs` |
| `seed_police.sql` | English police forces (police.uk slugs), generated by `data/build_police.mjs` |
| `functions/` | Edge Functions (routing, AI, delivery) |

Seeds run on `supabase start` (first time) and `supabase db reset`, in the order set in `config.toml`
`[db.seed] sql_paths`: `seed.sql`, `seed_authorities.sql`, `seed_police.sql`. All seeds are idempotent upserts.

`categories.extra_fields` is a JSON array of `{ key, label, type: "text"|"select"|"date", required, options?, hint? }`.
Values go in `reports.extra` as an object keyed by `key`.

## Reading data (anon or signed in)

- `categories`, `authorities`, `police_forces`: plain table reads.
- `public_reports` (view): safe columns only: `id, ref, category_id, category_slug, category_name, category_group,
  urgent, status, lat, lng, location_is_approximate, address_text, description, severity, reporter_display_name,
  duplicate_of, routed_authorities, police_force_id, still_there_count, follower_count, cover_photo_path,
  created_at, updated_at`. ASB/noise locations are rounded to 3 dp and their address is null.
- `public_report_updates` (view): `id, report_id, actor_type, kind, status_to, body, photo_path, created_at`.
- `report_photos`: public rows only (`is_public` and the report is public). Owners see all their own.
- `reports`, `report_updates`, `deliveries`: owners see their own rows; moderators see everything.
- Photos live in the **private** bucket `report-photos` at `<report_id>/<file>`. Use
  `storage.from('report-photos').createSignedUrl(path, ttl)`; the storage RLS allows it for public photos,
  your own uploads/reports, and moderators.

## RPCs (`supabase.rpc(name, args)`)

```sql
create_report(category_slug text, lat float8, lng float8,
              description text = null, address_text text = null, guest_email text = null,
              is_anonymous_public boolean = true, extra jsonb = '{}', severity text = null,
              ai_result jsonb = null, guest_name text = null, guest_phone text = null)
  returns table (id uuid, ref text)            -- anon + authenticated
  -- status 'submitted'; writes a 'status' timeline row; auto-follows for signed-in users.
  -- Validates England bbox, required extra fields, requires_address, email shape.

add_report_photo(report_id uuid, storage_path text, width int = null, height int = null,
                 contains_people boolean = null, contains_plates boolean = null)
  returns uuid                                  -- authenticated, report owner or moderator
  -- Upload the file first to report-photos/<report_id>/<file>. Max 3 per report.
  -- is_public = false when contains_people or contains_plates (moderator approves later).

reports_near(lat float8, lng float8, radius_m float8 = 1000, category_slugs text[] = null)
  returns setof nearby_report                   -- anon + authenticated; radius capped at 50 km, 500 rows
find_duplicates(category_slug text, lat float8, lng float8)
  returns setof nearby_report                   -- open reports, same category, within 25 m
  -- nearby_report = public_reports columns (minus routed_authorities, police_force_id,
  --                 follower_count) + distance_m

add_report_update(report_id uuid, kind update_kind, body text = null,
                  photo_path text = null, status_to report_status = null)
  returns bigint                                -- authenticated (anonymous sign-in OK)
  -- kind: 'still_there' | 'fixed' | 'comment' (anyone on a public report);
  -- 'status' + status_to: moderators only. 'fixed' by the reporter or a moderator sets status = fixed.
  -- Community photos: upload to <report_id>/updates/<your uid>/<file>.
```

## Writes by edge functions

Edge functions use the service-role key (bypasses RLS). When they change `reports.status` (e.g. `sent`,
`unrouted`) they should also insert a `report_updates` row (`actor_type 'system'`, `kind 'status'`,
`status_to`), because the table trigger does not log status changes automatically.

## Moderators

Set `profiles.is_moderator = true` in Studio (users cannot change it themselves). Moderators have full
access to every table via RLS.
